## 🎯 Приоритет 1: UX/UI улучшения

### 1.1 Индикатор силы пароля
**Проблема:** Пользователь не видит, насколько надежен его пароль

**Решение:**
- Добавить визуальный индикатор силы пароля (слабая/средняя/сильная/очень сильная)
- Цветовая индикация: красный → желтый → зеленый → темно-зеленый
- Показывать требования к паролю в реальном времени:
  - ✓ Минимум 8 символов
  - ✓ Содержит буквы
  - ✓ Содержит цифры (опционально)
  - ✓ Содержит спецсимволы (опционально)

**Файлы для изменения:**
- `backend/web/register.html` - добавить элемент индикатора
- `backend/web/scripts/auth-pages.js` - логика расчета силы пароля
- `backend/web/styles/auth.css` - стили индикатора

---

### 1.2 Показать/скрыть пароль
**Проблема:** Пользователь не может проверить правильность введенного пароля

**Решение:**
- Добавить иконку глаза (👁️) рядом с полями пароля
- При клике переключать тип input между `password` и `text`
- Добавить анимацию переключения

**Файлы для изменения:**
- `backend/web/login.html` - добавить кнопку показа/скрытия
- `backend/web/register.html` - добавить кнопки для обоих полей пароля
- `backend/web/scripts/auth-pages.js` - обработчик клика
- `backend/web/styles/auth.css` - стили кнопки

---

### 1.3 Валидация в реальном времени
**Проблема:** Ошибки показываются только после отправки формы

**Решение:**
- Валидация username при вводе (проверка формата, доступности)
- Валидация email при вводе (формат, доступность)
- Валидация пароля при вводе (сила, соответствие требованиям)
- Проверка совпадения паролей в реальном времени
- Визуальная индикация валидных/невалидных полей

**Файлы для изменения:**
- `backend/web/scripts/auth-pages.js` - добавить обработчики `input` и `blur`
- `backend/web/styles/auth.css` - стили для валидных/невалидных состояний

---

### 1.4 Улучшенные сообщения об ошибках
**Проблема:** Сообщения об ошибках могут быть неясными

**Решение:**
- Конкретизировать сообщения:
  - "Email уже зарегистрирован" → "Этот email уже используется. <a href='/login'>Войти?</a>"
  - "Имя пользователя занято" → "Имя 'username' уже занято. Попробуйте другое"
  - "Неверный пароль" → "Неверный пароль. <a href='mailto:support@power-chess.ru'>Забыли пароль?</a>"
- Показывать ошибки рядом с соответствующими полями
- Добавить иконки для типов ошибок

**Файлы для изменения:**
- `backend/web/scripts/auth-pages.js` - улучшить функцию `showFeedback` и `extractError`
- `backend/web/styles/auth.css` - стили для inline ошибок

## 🔒 Приоритет 2: Безопасность

### 2.1 Защита от ботов (CAPTCHA)
**Проблема:** Нет защиты от автоматической регистрации

**Решение:**
- Интегрировать Google reCAPTCHA v3 (невидимая) или hCaptcha
- Показывать CAPTCHA только при подозрительной активности
- Альтернатива: Cloudflare Turnstile

**Файлы для изменения:**
- `backend/web/register.html` - добавить скрипт CAPTCHA
- `backend/web/scripts/auth-pages.js` - отправка токена CAPTCHA
- `auth_service/app/routers/auth.py` - проверка токена на бэкенде

---

### 2.2 Rate Limiting на фронтенде
**Проблема:** Можно отправлять множество запросов подряд

**Решение:**
- Ограничить частоту отправки форм (минимум 2 секунды между попытками)
- Показывать таймер обратного отсчета при блокировке
- Визуальная индикация блокировки

**Файлы для изменения:**
- `backend/web/scripts/auth-pages.js` - добавить debounce/throttle

---

### 2.3 Проверка утечек паролей
**Проблема:** Пользователи могут использовать скомпрометированные пароли

**Решение:**
- Интегрировать Have I Been Pwned API (через хеширование первых 5 символов SHA-1)
- Предупреждать пользователя, если пароль найден в утечках
- Не блокировать регистрацию, только предупреждать

**Файлы для изменения:**
- `backend/web/scripts/auth-pages.js` - проверка через API
- `backend/web/styles/auth.css` - стили предупреждения

---

### 2.4 "Запомнить меня" для входа
**Проблема:** Пользователь вынужден входить каждый раз

**Решение:**
- Добавить чекбокс "Запомнить меня" на странице входа
- Увеличить срок жизни refresh token при включенной опции
- Сохранять предпочтение в localStorage

**Файлы для изменения:**
- `backend/web/login.html` - добавить чекбокс
- `backend/web/scripts/auth-pages.js` - обработка опции
- `auth_service/app/routers/auth.py` - увеличение срока жизни токена

---

## 🚀 Приоритет 3: Функциональность

- OAuth 2.0 интеграция
- Автоматическое создание аккаунта при первом входе

**Файлы для изменения:**
- `backend/web/login.html` - добавить кнопки соцсетей
- `backend/web/register.html` - добавить кнопки соцсетей
- `backend/web/styles/auth.css` - стили кнопок
- `auth_service/app/routers/auth.py` - обработка OAuth
- Новый сервис или модуль для OAuth провайдеров

---

### 3.2 Восстановление пароля
**Проблема:** Только email для восстановления, нет полноценного функционала

**Решение:**
- Создать страницу `/reset-password`
- Отправка email с токеном восстановления
- Страница смены пароля по токену
- Таймер действия токена (1 час)
- Защита от брутфорса (rate limiting)

**Файлы для изменения:**
- `backend/web/reset-password.html` - новая страница
- `backend/web/change-password.html` - страница смены пароля
- `backend/web/scripts/reset-password.js` - новый скрипт
- `auth_service/app/routers/auth.py` - эндпоинты восстановления
- `notifications_service` - отправка email

---

### 3.3 Двухфакторная аутентификация (2FA)
**Проблема:** Нет дополнительной защиты аккаунта

**Решение:**
- Опциональная 2FA через TOTP (Google Authenticator, Authy)
- QR-код для настройки
- Резервные коды для восстановления
- Настройка в профиле пользователя

**Файлы для изменения:**
- `backend/web/profile.html` - секция настроек 2FA
- `backend/web/scripts/2fa.js` - новый скрипт
- `auth_service/app/routers/auth.py` - эндпоинты 2FA
- Новые таблицы в БД для хранения секретов 2FA

---

### 3.4 Проверка доступности username/email
**Проблема:** Пользователь узнает о занятости только после отправки формы

**Решение:**
- AJAX проверка доступности username при вводе (debounce 500ms)
- AJAX проверка доступности email при вводе (debounce 500ms)
- Визуальная индикация (галочка/крестик)
- Сообщения: "Доступно" / "Уже занято"

**Файлы для изменения:**
- `backend/web/scripts/auth-pages.js` - AJAX запросы
- `auth_service/app/routers/auth.py` - эндпоинты проверки (`/api/auth/check-username`, `/api/auth/check-email`)
- `backend/web/styles/auth.css` - стили индикаторов

## ♿ Приоритет 5: Доступность (A11y)

### 5.1 Улучшение доступности
**Проблема:** Страницы могут быть неудобны для пользователей с ограниченными возможностями

**Решение:**
- Правильные ARIA-атрибуты (`aria-label`, `aria-describedby`, `aria-invalid`)
- Правильная навигация с клавиатуры (Tab, Enter, Escape)
- Фокус на первом поле при загрузке страницы
- Сообщения об ошибках связаны с полями через `aria-describedby`
- Контрастность текста (WCAG AA минимум)

**Файлы для изменения:**
- `backend/web/login.html` - добавить ARIA атрибуты
- `backend/web/register.html` - добавить ARIA атрибуты
- `backend/web/scripts/auth-pages.js` - управление фокусом

---

### 5.2 Поддержка скринридеров
**Проблема:** Пользователи скринридеров могут не понимать состояние формы

**Решение:**
- Живые регионы (`aria-live`) для сообщений об ошибках
- Правильные роли (`role="alert"` для ошибок, `role="status"` для успеха)
- Описание полей через `aria-describedby`

**Файлы для изменения:**
- `backend/web/login.html` - добавить `aria-live` регионы
- `backend/web/register.html` - добавить `aria-live` регионы

---
