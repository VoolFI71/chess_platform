### 2. Гибкая система кастомизации

Каждый модуль передает свои специфичные проверки через `pieceCheckCallback`:

```javascript
pieceCheckCallback: (piece, squareName) => {
  const classes = {};
  // Специфичная логика модуля
  if (isPlayersTurn && pieceBelongsToPlayer(piece, playerColor)) {
    classes.own = 'piece-own';
    // Проверка ходов...
    if (hasMoves) {
      classes.movable = 'piece-movable';
    }
  }
  return classes;
}
```

## Особенности реализации

### 1. Поддержка разных форматов фигур

- `games/computer`: использует `ChessPiecesSVG` и `div` для фигур
- `match`: использует `getPieceSVG` и `span` для фигур
- `tasks`: использует `getPieceSVG` и `span` для фигур

Все поддерживается через параметры `getPieceSVG` и `customPieceClasses.pieceTag`.

### 2. Делегирование событий в tasks

Модуль `tasks` использует делегирование событий вместо прямых обработчиков:
- `onSquareClick: null` в config
- Делегирование устанавливается отдельно после рендеринга

### 3. Постобработка координат в tasks

Координаты в `tasks` зависят от ориентации доски, поэтому:
- Сначала рендерим с базовыми координатами
- Затем исправляем их в постобработке

### 4. Дополнительные классы после рендеринга

Некоторые модули добавляют классы после рендеринга:
- `match`: `square-hoverable` для фигур игрока с ходами
- `tasks`: `clickable` для кликабельных клеток
