# Анализ информационной системы ChessMint

**Домашнее задание:** анализ информационного продукта на основе проекта шахматной платформы ChessMint.

---

## 1. Назначение разработки системы

### Для чего и кого мы её делаем

**ChessMint** — шахматная платформа для онлайн-школ (модель B2B2C):

- **Платформа** — ядро: игры (человек vs человек, человек vs компьютер), задачи (пазлы), инфраструктура, рейтинги, уведомления.
- **Школы** — арендаторы платформы: свои тренеры, ученики, брендинг.
- **Целевые пользователи:**
  - **Ученики** — играют, решают задачи, занимаются с тренерами.
  - **Тренеры** — ведут занятия, отслеживают прогресс учеников.
  - **Администраторы школ** — управляют тренерами, курсами, учениками.
  - **Администраторы платформы** — управляют школами и настройками системы.

**Формулировка:** «Шахматная платформа для онлайн-школ: игра, задачи и занятия с тренерами под управлением каждой школы».

### Как система будет развиваться

- **Фаза 1 (выполнена):** мультитенантность — школы, роли, изоляция данных.
- **Фаза 2:** панель школы и тренера — управление тренерами, учениками, отчёты.
- **Фаза 3:** группы, классы, домашние задания.
- **Фаза 4:** турниры (арена, швейцарская, круговая).
- **Фаза 5:** масштабирование — новые школы, брендинг, анализ партий движком, родительский доступ.

### Какую ценность должна приносить

- **Школам:** готовая инфраструктура для обучения (игры, задачи, рейтинги) без разработки с нуля.
- **Тренерам:** инструменты для работы с учениками и отслеживания прогресса.
- **Ученикам:** удобная среда для игры, тренировок и занятий с тренером.
- **Платформе:** монетизация через подписку школ, % от платежей или оплату за ученика.

## 2. Контекст внедрения

### Окружающий ИТ-ландшафт

| Компонент | Технология | Назначение |
|-----------|------------|------------|
| Backend | Python (FastAPI), Go (Gin) | Микросервисы: auth, users, payments, puzzles, notifications, games, computer_games, email |
| Frontend | Vanilla JS, HTML, CSS | SPA-подобные страницы, статика через backend |
| БД | PostgreSQL | Единая БД для всех сервисов |
| Шлюз | Nginx | Маршрутизация, SSL, балансировка |
| Хранилище | MinIO (S3-совместимое) | Файлы, изображения |
| Мониторинг | Prometheus, Grafana, Loki | Метрики, дашборды, логи |
| Контейнеризация | Docker, Docker Compose | Развёртывание и оркестрация |

### Интеграции с внешними ИС

| Внешняя система | Назначение | Способ интеграции |
|----------------|------------|-------------------|
| **YooKassa** | Приём платежей | REST API, webhook для подтверждения оплаты |
| **SMTP-сервер** | Отправка email (восстановление пароля, уведомления) | SMTP-протокол |
| **Stockfish** | ИИ для игры против компьютера | Локальный бинарник, UCI-протокол |

### Совместимость с технической и бизнес-средами

- **Техническая среда:** Linux, Docker, стандартные порты (80, 443, 5432, 8080). Совместимость с облачными провайдерами (AWS, Yandex Cloud и др.) через Docker.
- **Бизнес-среда:** B2B2C — платформа для B2B (школы), конечные пользователи — B2C (ученики и тренеры). Модель SaaS с мультитенантностью.

## 4. Анализ функциональных и нефункциональных требований

### Функциональные требования (ключевые)

- Аутентификация (JWT, регистрация, сброс пароля).
- Управление пользователями и профилями (рейтинг, статистика).
- Игры: создание, поиск соперника, ходы, завершение.
- Задачи: выдача по рейтингу, решение, учёт статистики.
- Уведомления в реальном времени (WebSocket).
- Платежи: создание заказа, webhook от YooKassa.
- Мультитенантность: школы, роли, фильтрация по school_id.

### Нефункциональные требования

| Требование | Реализация | Комментарий |
|------------|------------|-------------|
| **Производительность** | Кеш пазлов (stale-while-revalidate), TABLESAMPLE вместо ORDER BY random(), ETag для статики | Puzzles: p99 &lt; 50 ms при 3k RPS |
| **Масштабируемость** | Микросервисы, горизонтальное масштабирование сервисов | Каждый сервис можно масштабировать отдельно |
| **Расширяемость** | Модульная архитектура, общий модуль common | Добавление новых сервисов без изменения существующих |
| **Безопасность** | JWT для пользователей, internal tokens между сервисами, секреты в env | Изоляция сервисов, проверка входных данных (Pydantic) |
| **Надёжность** | PostgreSQL, рестарт сервисов (restart: unless-stopped), health checks | Восстановление после сбоев |
| **Стандартизация** | RESTful API, единые конвенции (RESTFUL_API.md) | Предсказуемые эндпоинты и коды ответов |
| **Стоимость** | Open-source стек (Python, Go, PostgreSQL, Nginx), Docker | Минимальные лицензионные расходы; затраты на хостинг и YooKassa |

### Дополнительные аспекты

- **Мониторинг:** Prometheus (метрики), Grafana (визуализация), Loki (логи) — операционная наблюдаемость.
- **Миграции:** централизованный сервис миграций, порядок применения по зависимостям.
- **Тестирование:** pytest (Python), go test (Go) — юнит- и интеграционные тесты.

## 5. Выводы

ChessMint — информационная система с чётким назначением (B2B2C-платформа для онлайн-школ), встроенная в современный ИТ-ландшафт (микросервисы, Docker, PostgreSQL). Бизнес-архитектура опирается на роли и мультитенантность. Нефункциональные требования (производительность, безопасность, расширяемость) учтены через кеширование, JWT, модульность и мониторинг. Система развивается поэтапно от MVP к полному функционалу турниров, групп и домашних заданий.
