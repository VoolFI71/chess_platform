# 🔍 Когда кеш может быть пустым (даже при TTL 30 минут)

## ❓ Вопрос
Как кеш может быть пустым, если он хранится 30 минут?

## ✅ Ответ: 7 сценариев, когда кеш пуст

### 1. **Первый запуск сервиса** 🚀
**Когда:** После перезапуска/деплоя сервиса  
**Почему:** Кеш хранится **в памяти процесса** (`_cache: dict[str, list[Puzzle]] = {}`)  
**Решение:** Первый запрос заполнит кеш, последующие будут быстрыми

```python
# Кеш в памяти - теряется при перезапуске
_cache: dict[str, list[Puzzle]] = {}
```

---

### 2. **Новые фильтры (новый cache_key)** 🔑
**Когда:** Пользователь запрашивает задачи с фильтрами, которых еще не было  
**Почему:** Каждая комбинация фильтров = отдельный ключ кеша  
**Пример:**
```python
# Первый запрос с этими фильтрами
rating_min=1400, rating_max=1600, themes=["fork"]
# → cache_key = "rmin_1400|rmax_1600|themes_fork"
# → Кеш пуст, нужно заполнить
```

**Решение:** После первого запроса кеш заполнится на 30 минут

---

### 3. **Слишком строгие фильтры (нет данных)** 📭
**Когда:** Фильтры не находят подходящих задач  
**Почему:** Код устанавливает пустой список в кеш (строка 209)

```python
# Если min_id is None or max_id is None
# → Нет задач с такими фильтрами
self._set_cache(cache_key, [])  # Пустой список!
```

**Пример:**
```python
# Запрос задач с рейтингом 5000 (не существует)
rating_min=5000, rating_max=6000
# → min_id = None, max_id = None
# → Кеш = [] (пустой список)
```

**Решение:** Возвращать 404 сразу, не кешировать пустой результат

---

### 4. **Ошибка при обновлении кеша** 💥
**Когда:** Обновление кеша падает с исключением  
**Почему:** Кеш остается пустым или устаревшим

```python
try:
    await self._refresh_cache(session, cache_key, filters)
except Exception as e:
    logger.error(f"Error refreshing cache: {e}")
    # Кеш НЕ обновлен, остается пустым или старым
```

**Решение:** Логировать ошибки, использовать stale-while-revalidate

---

### 5. **Race condition (гонка)** ⚡
**Когда:** Несколько запросов одновременно при пустом кеше  
**Почему:** Между проверкой и заполнением кеша может пройти время

```python
# Запрос 1: проверяет кеш → пуст → начинает заполнять
# Запрос 2: проверяет кеш → еще пуст → тоже начинает заполнять
# Оба используют прямой запрос к БД
```

**Решение:** Блокировка `_refresh_lock` предотвращает это, но есть окно

---

### 6. **TABLESAMPLE не нашел задачи** 🎲
**Когда:** TABLESAMPLE вернул 0 результатов после фильтрации  
**Почему:** Случайная выборка может не содержать задач с нужными фильтрами

```python
# TABLESAMPLE выбирает 1% таблицы
# Но после фильтрации по themes/opening_tags может быть 0 результатов
items = list(result.scalars().all())  # []
if not items:  # → Fallback метод
```

**Решение:** Fallback на случайное смещение, но это медленнее

---

### 7. **Кеш истек, но обновление еще не завершилось** ⏳
**Когда:** Кеш устарел (>30 минут), обновление запущено в фоне, но еще не готово  
**Почему:** Обновление асинхронное, может занять время

```python
# Кеш устарел → запускаем обновление в фоне
self._refresh_tasks[cache_key] = asyncio.create_task(...)

# Но если кеш был пуст или устарел → используем прямой запрос
if cached:  # False, если кеш пуст
    return random.choice(cached)
# → Используем _get_random_with_tablesample (медленно)
```

**Решение:** Stale-while-revalidate - используем старый кеш, пока обновляется

---

## 📊 Статистика сценариев

| Сценарий | Частота | Влияние на производительность |
|----------|---------|-------------------------------|
| Первый запуск | Редко (при деплое) | Высокое (1-5 сек) |
| Новые фильтры | Часто (новые пользователи) | Высокое (1-5 сек) |
| Строгие фильтры | Редко | Среднее (50-200ms) |
| Ошибки обновления | Редко | Высокое (1-5 сек) |
| Race condition | Редко | Среднее (50-200ms) |
| TABLESAMPLE пуст | Средне | Среднее (50-200ms) |
| Обновление в процессе | Часто | Низкое (stale cache) |

## 🔧 Улучшения кода

### Проблема 1: Пустой кеш при отсутствии данных

**Текущий код:**
```python
if min_id is None or max_id is None:
    self._set_cache(cache_key, [])  # ❌ Кешируем пустой список
    return
```

**Проблема:** Пустой список в кеше означает, что следующие 30 минут все запросы будут возвращать None

**Решение:** Не кешировать пустой результат, возвращать None сразу

### Проблема 2: Нет проверки на пустой список

**Текущий код:**
```python
if cached and not self._should_refresh(...):
    return random.choice(cached)  # ❌ Может быть []
```

**Проблема:** Если `cached = []`, `random.choice([])` упадет с ошибкой

**Решение:** Проверять `len(cached) > 0`

---

## ✅ Рекомендации

1. **Не кешировать пустые результаты** - если нет данных, не сохранять `[]` в кеш
2. **Проверять длину кеша** - перед `random.choice()` проверять `len(cached) > 0`
3. **Увеличить TTL для стабильных фильтров** - популярные комбинации можно кешировать дольше
4. **Warm-up кеша** - при старте сервиса заполнять кеш для популярных фильтров
5. **Мониторинг** - логировать случаи, когда кеш пуст
