# Руководство по нагрузочному тестированию оптимизаций

## Быстрый старт

### 1. Базовый тест (для оценки оптимизаций)

```bash
# Тест с 1000 запросов, последовательно (конкурентность = 1)
python load_test.py --url http://localhost:8080 --requests 1000 --concurrent 1

# Тест с конкурентностью 10
python load_test.py --url http://localhost:8080 --requests 1000 --concurrent 10

# Сохранение результатов в JSON
python load_test.py --url http://localhost:8080 --requests 1000 --concurrent 1 --save results_after.json
```

### 2. Сравнение до и после оптимизаций

#### Шаг 1: Тест ДО оптимизаций (если есть старая версия)
```bash
# Запустите старую версию сервиса, затем:
python load_test.py --url http://localhost:8080 --requests 1000 --concurrent 1 --save results_before.json
```

#### Шаг 2: Тест ПОСЛЕ оптимизаций
```bash
# Запустите новую версию сервиса с оптимизациями, затем:
python load_test.py --url http://localhost:8080 --requests 1000 --concurrent 1 --save results_after.json
```

#### Шаг 3: Сравнение результатов
```bash
python load_test.py --compare results_before.json results_after.json
```

### 3. Тест с постоянной нагрузкой

```bash
# Тест в течение 60 секунд с 10 конкурентными запросами
python load_test.py --url http://localhost:8080 --mode duration --duration 60 --concurrent 10
```

## Новые метрики

Скрипт теперь измеряет:

### Размер ответа
- **Средний размер (сжатый)** - размер ответа после сжатия
- **Средний размер (несжатый)** - оценка размера до сжатия
- **Коэффициент сжатия** - процент уменьшения размера

### Тип сжатия
- **gzip** - GZip сжатие
- **brotli** - Brotli сжатие (если поддерживается)
- **без сжатия** - если сжатие не применяется

### Время передачи данных
- Среднее и медианное время передачи данных по сети

## Примеры использования

### Оценка эффекта оптимизаций

```bash
# 1. Запустите сервер с оптимизациями
# 2. Выполните тест
python load_test.py \
  --url http://localhost:8080 \
  --requests 1000 \
  --concurrent 1 \
  --save results.json

# 3. Проверьте результаты
cat results.json
```

### Сравнение производительности

```bash
# Тест 1: Базовый (если есть старая версия)
python load_test.py --url http://localhost:8080 --requests 1000 --concurrent 1 --save before.json

# Тест 2: С оптимизациями
python load_test.py --url http://localhost:8080 --requests 1000 --concurrent 1 --save after.json

# Сравнение
python load_test.py --compare before.json after.json
```

### Тест под нагрузкой

```bash
# Высокая конкурентность для проверки стабильности
python load_test.py \
  --url http://localhost:8080 \
  --requests 5000 \
  --concurrent 50 \
  --save stress_test.json
```

## Интерпретация результатов

### Время ответа
- **Среднее время < 5 мс** - отлично
- **99-й процентиль < 10 мс** - хорошо
- **Стандартное отклонение < 2 мс** - стабильная производительность

### Размер ответа
- **Коэффициент сжатия > 60%** - хорошее сжатие JSON
- **Средний размер < 500 байт** - компактные ответы

### Пропускная способность
- **> 150 req/sec** при конкурентности 1 - отлично
- **> 500 req/sec** при конкурентности 10 - хорошо

## Ожидаемые улучшения после оптимизаций

После применения оптимизаций (orjson, уменьшенный GZip порог, exclude_none):

1. **Время ответа**: снижение на 10-20% за счет быстрой сериализации
2. **Размер ответа**: уменьшение на 15-25% за счет exclude_none и лучшего сжатия
3. **Пропускная способность**: увеличение на 20-30% за счет меньшего размера и быстрой сериализации
4. **Коэффициент сжатия**: улучшение на 5-10% за счет меньшего порога GZip

## Устранение проблем

### Сервер не отвечает
```bash
# Проверьте, что сервер запущен
curl http://localhost:8080/api/puzzles/random
```

### Ошибки подключения
```bash
# Увеличьте таймаут
python load_test.py --url http://localhost:8080 --requests 100 --concurrent 1
```

### Низкая пропускная способность
- Проверьте нагрузку на сервер
- Убедитесь, что кеш прогрет
- Проверьте сетевые задержки (ping)
