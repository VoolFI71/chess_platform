# 🎯 Архитектура: Задачи только из кеша

## ✅ Изменения

### Убрано
- ❌ Прямые запросы к БД при пустом кеше
- ❌ Метод `_get_random_with_tablesample()` для прямых запросов
- ❌ Fallback на `ORDER BY random()` при пустом кеше
- ❌ Параметр `session` из `get_random_puzzle()` (больше не нужен)

### Оставлено
- ✅ Кеш в памяти (30 минут TTL)
- ✅ Фоновое обновление кеша через TABLESAMPLE
- ✅ Stale-while-revalidate (используем старый кеш, пока обновляется)
- ✅ Проверка на пустой кеш перед `random.choice()`

---

## 🔄 Как работает сейчас

### Сценарий 1: Кеш есть и свежий (<30 минут)
```
Запрос → Проверка кеша → Возврат задачи из кеша (<1ms)
```

### Сценарий 2: Кеш устарел (>30 минут)
```
Запрос → Проверка кеша → Кеш устарел
       → Запуск обновления в фоне
       → Возврат задачи из старого кеша (stale-while-revalidate)
       → Следующий запрос получит свежий кеш
```

### Сценарий 3: Кеш пуст (первый запрос)
```
Запрос → Проверка кеша → Кеш пуст
       → Запуск обновления в фоне
       → Возврат None (404)
       → Следующий запрос получит задачу из кеша
```

---

## 📊 Преимущества

### 1. **Стабильная производительность**
- Все запросы из кеша = всегда быстро (<1ms)
- Нет медленных запросов к БД

### 2. **Меньше нагрузки на БД**
- Запросы к БД только при обновлении кеша (раз в 30 минут)
- TABLESAMPLE используется только для обновления кеша

### 3. **Простота**
- Убрана сложная логика fallback'ов
- Один путь выполнения: кеш → задача

---

## ⚠️ Важные моменты

### Первый запрос после перезапуска
- **Проблема:** Кеш пуст → возвращается 404
- **Решение:** 
  1. Warm-up кеша при старте сервиса (опционально)
  2. Или пользователь делает повторный запрос через 1-2 секунды

### Новые фильтры
- **Проблема:** Новый cache_key → кеш пуст → 404
- **Решение:** Первый запрос вернет 404, второй запрос получит задачу

### Слишком строгие фильтры
- **Проблема:** Нет задач с такими фильтрами → кеш не заполняется
- **Решение:** Возвращается 404 с сообщением "Попробуйте изменить фильтры"

## 🔧 Рекомендации

### 1. Warm-up кеша при старте (опционально)

```python
# В main.py или при старте сервиса
async def warmup_cache():
    cache = get_puzzle_cache()
    # Заполняем кеш для популярных фильтров
    popular_filters = [
        None,  # Все задачи
        PuzzleFilters(rating_min=1400, rating_max=1600),
        PuzzleFilters(rating_min=1600, rating_max=1800),
    ]
    async with SessionLocal() as session:
        for filters in popular_filters:
            await cache.get_random_puzzle(filters)
            # Запустит обновление кеша в фоне
```

### 2. Увеличить размер кеша (если память позволяет)

```python
# В config.py
random_pool_size: int = 20000  # Вместо 15000
```

### 3. Мониторинг пустых кешей

```python
# Логировать случаи, когда кеш пуст
if not puzzle:
    logger.warning(f"Cache empty for filters: {filters}")
```
