> Документ создан на основе анализа проекта и обсуждения стратегии.  
> Дата: март 2025

---

## 1. Позиционирование продукта

**Целевая модель:** Шахматная платформа для множества онлайн-школ (B2B2C).

- **Платформа** — ядро: игры, задачи, инфраструктура.
- **Школы** — арендаторы: свои тренеры, курсы, ученики, брендинг.
- **Первая школа** — ваша, как пилотный клиент.

**Формулировка:** «Шахматная платформа для онлайн-школ: игра, задачи, курсы и занятия с тренерами под управлением каждой школы».

## 4. Архитектура мультитенантности

### 4.1. Модель данных (ключевые изменения)

```
schools (id, name, slug, subdomain, logo_url, settings_json, ...)
users (..., school_id nullable)  # platform_admin — school_id = null
courses (..., school_id)
coaches (..., school_id)
enrollments (user_id, course_id)  # course уже привязан к school
groups (id, school_id, coach_id, name, ...)
group_members (group_id, user_id)
```

### 4.2. Роли

| Роль | Описание | Доступ |
|------|----------|--------|
| `platform_admin` | Админ платформы | Все школы, настройки, мониторинг |
| `school_admin` | Админ школы | Своя школа: тренеры, курсы, ученики |
| `coach` | Тренер | Свои группы, ученики, назначение ДЗ |
| `student` | Ученик | Курсы, задачи, игры |
| `parent` | Родитель | Прогресс своих детей |

### 4.3. Изоляция

- Все запросы фильтруются по `school_id` текущего пользователя.
- Platform admin может переключать контекст школы.
- Общие ресурсы (игры, задачи) — без привязки к школе или с опциональной фильтрацией.

## 5. Этапы реализации

### Фаза 1: Фундамент мультитенантности (2–4 недели) ✅
1. ✅ Миграции: таблица `schools`, `school_id` в users, courses.
2. ✅ Роли (student, coach, school_admin, platform_admin) в users.
3. ✅ Школа ChessMint как первый tenant (school_id = 1).
4. ✅ API: CRUD школ (только для platform_admin).
5. ✅ Фильтрация по school_id в courses (query param).
6. ✅ Прогресс по урокам (lesson_completions, POST complete, GET progress).
7. ✅ Панель тренера MVP (/coach-panel, список учеников школы).

### Фаза 2: Панель школы и тренера (3–4 недели)
1. Панель school_admin: управление тренерами, курсами, учениками.
2. Панель coach: список учеников, группы, базовые отчёты.
3. Прогресс по урокам (lesson_completions).

### Фаза 3: Группы и домашние задания (2–3 недели)
1. Группы, привязка учеников.
2. Назначение задач/уроков как ДЗ.
3. Отображение выполнения в панели тренера.

### Фаза 4: Турниры (3–4 недели)
1. Модель турнира (school_id, format, status).
2. Регистрация, жеребьёвка.
3. Проведение партий, учёт результатов.

### Фаза 5: Масштабирование (по мере необходимости)
1. Подключение второй школы.
2. Брендинг (поддомены, настройки).
3. Анализ партий движком.
4. Родительский доступ.
